\section{KVP10k Dataset}
\label{sec:kvp10k}

The KVP10k dataset \cite{kvp10k} is a large-scale benchmark for \kvp{} extraction from business documents. It contains 10,707 unique pages: 9,656 training pages and 1,051 test pages. The released data contain 48,280 training and 5,255 test annotation rows because pages have multiple annotator copies. The pages span diverse document types including invoices, forms, and receipts.

\subsection{Data Collection and Annotation Format}
The dataset was collected by IBM Research from real-world business documents, with manual annotation of bounding boxes and key-value relationships. Each raw row contains an annotator copy for a page together with a list of annotations. Fields relevant to this analysis include a \texttt{label}, optional polygon \texttt{coordinates} (a list of $\{x, y\}$ points), and an optional \texttt{attributes.Linking} reference that encodes a key--value relationship. Coordinate availability differs across annotator copies of the same page.

The downstream preparation pipeline operates on unique page hashes and produced 5{,}389 usable training pages and 581 usable test pages. These prepared pages are distinct from the duplicated raw rows used by the Stage~2 analysis below.

\section{Annotation-Geometry Clustering Analysis}
\label{sec:layout_clustering}

We perform exploratory unsupervised clustering of annotation-box geometry. This provides a compact way to audit coordinate availability and density and to stratify evaluation in later stages. As detailed below, the fitted clusters are annotation-row regimes rather than document genres or independently validated visual-layout classes.

\subsection{Feature Extraction}
\label{subsec:features}

We extract 13 geometric summary features per raw annotation row (see Table \ref{tab:features}). A row represents one annotator copy of a page; if its annotations contain no usable polygon coordinates, the feature extractor returns an all-zero vector.

In the checked-in extractor, $\rho$ is assigned exactly the same value as $A_{\text{total}}$. The saved 13-column representation therefore contains 12 distinct signals; the duplicate is retained here to describe the executed analysis faithfully.

\subsection{K-means Clustering}
\label{subsec:kmeans}

We apply K-means clustering \cite{kmeans} on standardized geometry features. To select the number of clusters, we sweep $k \in \{2,\dots,10\}$ and evaluate multiple complementary criteria: (i) Silhouette score (primary), (ii) Davies--Bouldin index, (iii) Calinski--Harabasz score, and (iv) the inertia curve (elbow). We use a fixed random seed and standardization to make the selection reproducible.

Figure~\ref{fig:stage2_optimal_k} summarizes the selection outcome. Across the considered range, the criteria favor a small number of clusters. In particular, the silhouette score peaks at \textbf{0.763} for $k=2$ (0.7627), and we therefore choose \textbf{$k=2$}. This high separation must be interpreted together with the duplicate-row and all-zero-feature effect described below.

The Stage~2 input consists of 25{,}692 training annotation rows selected because their annotation lists are non-empty. These rows correspond to 9{,}124 unique page hashes and are separate from the later PyMuPDF-prepared data. For every represented page, exactly one row contains usable polygon coordinates; the other annotator copies do not. Consequently, 16{,}568 duplicate rows produce all-zero feature vectors. The analysis therefore identifies two coordinate-availability regimes: rows with substantial annotation-box geometry and rows with little or no usable geometry. It does not establish distinct document genres or visual-layout types.

\subsection{Use in Later Stages}
\label{subsec:cluster_use}

The scaler and $k$-means model are fitted on the 25{,}692 raw training rows
described above. For later evaluation, the model is kept fixed, but test rows
are first grouped by page hash and the annotator copy with the largest number
of coordinate boxes is selected for each unique page. Its features are then
transformed by the training-fitted scaler and assigned to the nearest cluster.
This avoids assigning a page from an empty duplicate copy. Per-cluster results
in Stages~3--4 are measured on held-out test pages, but should be interpreted as
stratification by annotation-geometry density rather than document genre (see
Section~\ref{sec:stage3-per-cluster}).

\section{Key-Value Link Analysis}
\label{sec:kv_analysis}

We analyze spatial relationships between linked \kvps{} to inform model design.

\subsection{Spatial Proximity}

For each key-value pair with linking annotation, we compute the Euclidean distance between bounding box centers:

\begin{equation}
d_{kv} = \sqrt{(x_v - x_k)^2 + (y_v - y_k)^2}
\end{equation}

where $(x_k, y_k)$ and $(x_v, y_v)$ are the normalized center coordinates of the key and value boxes.

On a 200-row annotation subset containing 755 links,\footnote{The subset was formed from the first 200 training rows with non-empty annotation lists. It represents 70 unique page hashes, of which 69 contribute coordinate-bearing rows. This exploratory raw-row subset is distinct from the 581-page evaluation set (3{,}776 ground-truth links) reported in Chapter~\ref{ch:exresults}.} linked pairs tend to be proximate: the mean key--value distance is $\mu_d = 0.120$, the median is $\tilde{d} = 0.095$, and the 90th percentile is $d_{90} = 0.239$ (all in normalized coordinate units). The proximity pattern suggests that spatial features may be informative for linking.

\section{Summary}
\label{sec:dataset_summary}

The analysis yields three main observations. First, the original clustering primarily separates coordinate-bearing annotation rows from duplicate rows with little or no usable geometry, so it should not be interpreted as document-genre discovery. Second, linked \kvps{} in the sampled rows tend to be spatially proximate, suggesting that spatial features may aid linking. Third, the 200-row subset contains substantial key--value linking annotation. These findings motivate spatial encoding in the linker while placing clear limits on the interpretation of the clustering results.
