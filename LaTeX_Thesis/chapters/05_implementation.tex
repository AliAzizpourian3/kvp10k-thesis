\chapter{Implementation and Experimental Setup}
\label{ch:implementation}

\section{Implementation Scope and Ownership}
\label{sec:system-architecture}

The implementation contains two model paths. The first is a reconstructed
Mistral-7B generative reference system based on the published KVP10k
baseline~\cite{kvp10k,mistral}. It is a local re-implementation, not an exact
reproduction of the published system. The second path is the
LayoutLMv3-based discriminative system described in
Chapter~\ref{ch:methodology}.

KVP10k, Mistral-7B, the pretrained LayoutLMv3-base encoder, the Hugging Face
Transformers library, and the released KVP10k evaluator are prior resources.
The data preparation and input conversion, adapted Mistral prompt and output
handling, task-specific entity classifier and relation linker, span grouping,
training procedures, evaluator integration, and diagnostic checks were
implemented for this thesis. The general LoRA, QLoRA, and scaled-dot-product
principles are also prior work~\cite{lora,qlora,vaswani2017attention}.

\section{Prepared Data and Split Isolation}
\label{sec:data-preprocessing}

The preparation pipeline converts the available KVP10k rows into one JSON
record per usable page. Each record contains extracted page text, bounding
boxes on a quantised $100\times100$ grid, aligned KVP annotations, the
LMDX-style document representation, and the generative target. Chapter~3
describes the official dataset splits and all preparation exclusions.

The two model paths use different subsets of the 5{,}389 prepared pages from
the official training split. The reconstructed Mistral system uses 4{,}985
pages with non-empty serialised targets; 404 empty-target pages are excluded
by its training loader. The discriminative path uses fixed manifests containing
4{,}851 training pages and 538 validation pages. These manifests were produced
once with seed 42, do not overlap, and remain unchanged for entity pretraining
and final joint training.

The prepared official-test subset contains 581 pages. It is not part of either
training set or the discriminative validation set. The bbox-scale-fixed
discriminative training loaders expose only the fixed training and validation
manifests. They do not construct a test loader, and test metrics do not
participate in checkpoint selection or early stopping.

\section{Reconstructed Mistral-7B Reference System}
\label{sec:mistral-implementation}

\subsection{Text Extraction and Prompt Input}
\label{sec:text-processing}

The local preparation path obtains text and word boxes from the PDF text layer
with PyMuPDF~\cite{pymupdf}. It does not run the optical character recognition
pipeline used by the published KVP10k baseline. Pages without a usable text
layer are therefore absent from the prepared subset.

Extracted words are grouped into line-like blocks. Each block is serialised as
\texttt{text x1|y1|x2|y2}, where the coordinates are quantised to integers on
the $100\times100$ page grid. The blocks are inserted into the LMDX-style
prompt~\cite{lmdx} shown in Figure~\ref{fig:stage3-prompt}.

\subsection{Target Serialisation and Final Parser}
\label{sec:mistral-prompt-output}

Target entries are sorted by their vertical and then horizontal entity centres.
The target is a Python list-of-lists string. A Regular item contains a located
key string and a located value string. An Unkeyed item contains a canonical
category string without a box and a located value string. An Unvalued item is
serialised as a singleton list containing one located key string. Thus, the
singleton representation used for Unvalued supervision is an explicit
extension of the literal two-string instruction in the prompt.

The final inference parser uses \texttt{ast.literal\_eval} rather than executing
generated text. It interprets singleton lists as Unvalued predictions. It
recognises an Unkeyed prediction when a boxless first string equals one of the
canonical labels \texttt{name}, \texttt{date}, \texttt{address},
\texttt{amount}, \texttt{phone}, \texttt{email}, \texttt{website},
\texttt{year}, \texttt{document type}, \texttt{document title}, and
\texttt{text}. It also accepts \texttt{implicit} followed by one of these
labels. A two-element entry whose second string is \texttt{not presented}
becomes Unvalued. Any other entry with at least two elements becomes Regular;
elements after the first two are ignored. A final suffix is parsed as a box
only when it contains four integers. Otherwise, the complete string remains
plain text without a box. Malformed top-level outputs produce an empty
prediction list, and malformed entries are counted and skipped.

For each page, inference stores both the raw generated response and the parsed
\texttt{kvps\_list}. Keeping the raw response permits deterministic re-parsing
without another model inference run and separates generation errors from
parser errors.

\subsection{QLoRA Training}
\label{sec:mistral-training}

The reconstructed reference system fine-tunes
\texttt{mistralai/}\linebreak[4]\texttt{Mistral-7B-Instruct-v0.2}~\cite{mistral}. QLoRA loads the
base model with 4-bit NormalFloat4 quantisation, double quantisation, and
bfloat16 computation~\cite{qlora}. LoRA adapters use rank $r=4$, scaling
parameter $\alpha=4$, dropout $0.05$, and no bias~\cite{lora}. They target the
query, key, value, and output projections and the up and down projections of
the feed-forward layers.

Training uses the Hugging Face Transformers Trainer
implementation~\cite{wolf2020transformers}, paged 8-bit
AdamW~\cite{bitsandbytes}, learning rate
$5\times10^{-4}$, batch size 1, gradient accumulation over 4 batches, maximum
sequence length 8{,}192, and seed 0. The 4{,}985 usable prepared training pages
are processed for a fixed eight epochs. Prompt and padding tokens receive the
ignore label $-100$, so the causal language-model loss is applied only to the
serialised response.

No validation or test metric is calculated during this training run. The
Trainer evaluation strategy is disabled, and there is no metric-based
checkpoint selection. The final checkpoint saved after the fixed eight-epoch
schedule is used for the separate inference step.

\subsection{Inference}
\label{sec:mistral-inference}

Final inference loads the saved adapter checkpoint only after training is
complete. Each of the 581 prepared test prompts is truncated to at most 8{,}192
input tokens. Greedy generation uses no sampling and permits at most 2{,}048
new tokens. The output checks require exactly one raw-response file and one
parsed-prediction file for every prepared test page before the official
evaluation wrapper is called.

\section{Discriminative Input Pipeline}
\label{sec:layout-encoding}

\subsection{Word and Label Construction}
\label{sec:data-loader}

The discriminative loader reads the same prepared page records. Each
multi-word LMDX block is split at whitespace. The original block box is divided
horizontally according to the character offsets of the resulting words. This
produces word-level inputs and supports separate labels for words that
previously shared one block.

The annotation-to-word alignment labels every matched word as
\texttt{KEY}, \texttt{VALUE}, or \texttt{O}. The label \texttt{O} denotes a
token that belongs to neither entity class. A word matches an annotation region
when the intersection covers at least 50\% of either the annotation box or the
word box. For each Regular KVP with recovered key and value words, the first
matched key word and first matched value word define one representative
word-level relation. The labels are expanded to subword tokens by the
LayoutLMv3 word-ID mapping and later collapsed to span-pair targets.

\subsection{LayoutLMv3 Coordinate Mapping and Visual Input}
\label{sec:image-processing}

The prepared word coordinates already use the integer range $[0,100]$. The
final loader maps each prepared coordinate $c$ to the LayoutLMv3 input grid as
\[
  c_{\mathrm{model}}
  =10\,\operatorname{int}\!\left(\min(100,\max(0,c))\right).
\]
It does not divide the prepared coordinates by the PDF image width or height.
The resulting model-input boxes use $[0,1000]$. In contrast, decoded prediction
boxes are unions of the original prepared word boxes and remain on the
$[0,100]$ grid required by the local KVP10k representation.

The maximum text sequence length is 512 tokens. Longer pages are truncated.
Page-image loading is disabled. The LayoutLMv3 processor instead receives a
solid-white $224\times224$ RGB placeholder for every page and produces the
same constant visual tensor. The discriminative models therefore receive
page-specific text and layout input but no page-specific image content.

\section{Discriminative Model Implementation}
\label{sec:model-implementation}

\subsection{Components and Development Variants}
\label{sec:layoutlmv3-integration}

The implementation loads the pretrained
\texttt{microsoft/layoutlmv3-base} encoder~\cite{layoutlmv3}. V1 adds the
thesis-specific three-class entity classifier and a token-pair relation linker.
V2 changes the relation candidates from tokens to contiguous entity spans. V3
is a linker-only diagnostic that reuses the V2 span architecture, freezes the
encoder and classifier, and forms candidates from their predicted labels. The
final LayoutLMv3-based span-level discriminative model (V4) jointly fine-tunes
the encoder, classifier, and linker. V3 has no separate headline benchmark
result.

The entity classifier applies dropout with probability $0.1$ and maps each
768-dimensional text-token representation to three raw class logits in the
order \texttt{O}, \texttt{KEY}, and \texttt{VALUE}. Softmax converts them to
class probabilities, and \texttt{argmax} selects the predicted label. Training
applies unweighted cross-entropy to active text-token positions.

\subsection{Span Construction and Relation Decoding}
\label{sec:entity-classifier-impl}

The span-level path groups consecutive tokens that have the same non-\texttt{O}
label. Only the all-zero box $[0,0,0,0]$, used by special and padding
positions, is excluded. A zero-width or zero-height box is not rejected solely
for that reason. Each span representation is the mean of its token
representations, and its output box is the union of the constituent raw word
boxes.

During V4 training, ground-truth entity labels supply the spans used for
relation supervision. During validation and inference, predicted entity labels
supply them. V4 therefore uses teacher-forced span construction during training
and predicted-span construction at evaluation time.

The linker produces one raw relation logit for every retained candidate pair
composed of one \texttt{KEY} span and one \texttt{VALUE} span. Sigmoid converts a
relation logit to a relation probability. For each key span, the decoder selects
the value span with the largest relation probability and emits the pair only
when this probability is at least $0.5$. The probability threshold is a
decoding rule. It is distinct from the binary relation loss and from the
benchmark precision, recall, and F1 metrics.

\subsection{Numerical Safeguards and Candidate Limits}
\label{sec:linker-impl}

The relation linker computes candidate-pair logits in chunks of at most eight
\texttt{KEY} candidates. V1 retains at most 128 \texttt{KEY} tokens and 128
\texttt{VALUE} tokens per page. The
span-level variants retain at most 64 key spans and 64 value spans. When a
limit is exceeded, V1 ranks tokens by their entity-class probability, while
the span-level path ranks spans by their mean entity-class probability.

The distance calculation and small denominators in the spatial features receive
an additive $10^{-8}$ term, and the value-to-key area ratio is capped at 50.
The projected semantic compatibility component is clamped to $[-20,20]$ before it is
combined with the spatial representation. For the relation loss only, the
resulting raw relation logits are clamped to $[-10,10]$. Binary relation targets
outside $[0,1]$ are masked before binary cross-entropy with logits is applied.
The positive and negative counts are each lower-bounded by 1 before the
positive-class weight is calculated as the negative-to-positive ratio and
capped at 50. These operations affect loss stability. They do not replace the inference
sigmoid or its probability threshold.

The training loop checks entity losses, relation losses, combined losses,
relation logits, and gradient norms for finite values. Gradient clipping uses
maximum norm 1.0. These checks stop the run on a non-finite value instead of
silently continuing.

\section{Discriminative Training and Checkpoint Selection}
\label{sec:training-pipeline}

\subsection{Entity-Classification Pretraining}
\label{sec:stage4-training-loop}

The first phase trains the LayoutLMv3 encoder and entity classifier while the
relation linker is disabled. It uses the fixed 4{,}851/538
training/validation manifests, fp32 precision, batch size 4, gradient
accumulation over 8 batches, learning rate $5\times10^{-5}$, weight decay
$0.01$, and seed 42. Each epoch contains 152 optimiser updates, and the first
152 updates are used for linear warm-up. Early stopping uses patience 3, and
training runs for at most 10 epochs. Validation uses
token-level class-aware \texttt{KEY}/\texttt{VALUE} micro F1, which counts a
\texttt{KEY}-to-\texttt{VALUE} or \texttt{VALUE}-to-\texttt{KEY} error as both
a false positive for the predicted class and a false negative for the target
class. Epoch 10 is the selected entity checkpoint. No test data is accessed in
this phase.

\subsection{Final Joint V4 Training}
\label{sec:v4-joint-training}

Final joint training loads the selected entity encoder and classifier from the
first phase and creates a fresh, randomly initialised relation linker. It then jointly optimises
all three components. This separates the entity initialisation from the new
relation parameters and does not reuse the linker from an earlier joint
checkpoint.

V4 uses fp32 precision, batch size 1, gradient accumulation over 8 batches,
AdamW \cite{loshchilov2019decoupled}, learning rate $2\times10^{-5}$, weight
decay $0.01$, and relation-loss weight 5.0. The maximum is 30 epochs. The
scheduler advances once per optimiser update. With 4{,}851 training
microbatches, each epoch contains
$\lceil 4851/8\rceil=607$ optimiser updates. The complete schedule therefore
contains at most 18{,}210 updates, of which the first 500 are linear warm-up
updates. The final accumulation window contains three microbatches, so its loss
is divided by three rather than eight before the optimiser step.

Checkpoint selection requires a strict improvement in the official validation
Regular text+location macro pair F1 calculated from predicted spans at relation
probability threshold $0.5$. Early stopping is permitted from epoch 10 and uses
patience 5. Test metrics are not used for either decision. Training stops after
epoch 20, and checkpoint 15 is the validation-selected final joint V4
checkpoint.

After checkpoint selection was complete, the selected checkpoint was evaluated once on the 581-page test subset.

\subsection{Checkpoint State}
\label{sec:checkpointing}

Each completed V4 epoch stores model weights and the complete training state.
The state contains the optimiser, scheduler, gradient scaler, completed epoch,
global optimiser step, best validation value, early-stopping counter, training
history, run configuration, and Python, NumPy, PyTorch, CUDA, and data-loader
random states. Resume restores this state and checks the saved configuration.
The selected checkpoint is then reloaded strictly before the training phase is
closed.

Exact checkpoint hashes, absolute paths, job identifiers, and hardware
allocation history remain in the repository run manifests and logs. They are
not repeated in the main manuscript.

\section{Inference and Official Evaluation}
\label{sec:evaluation-protocol}

\subsection{Prediction Export}
\label{sec:baseline-eval-pipeline}

The Mistral path exports the type-aware predictions produced by the final
parser. The direct V4 decoder exports Regular linked span pairs. It does not
convert unmatched spans into singleton predictions. Any separate recovery of
Unkeyed or Unvalued items is a post-processing variant and is not part of the
direct Regular output.

For V4, softmax first produces the entity-class probabilities. Predicted
non-\texttt{O} labels form spans. The linker then produces raw relation logits,
sigmoid converts them to probabilities, the best value is selected for each
key, and the fixed $0.5$ probability threshold determines whether a Regular
pair is emitted. Emitted pairs are ordered by decreasing relation probability
before their text and boxes are passed to the greedy evaluator.

\subsection{Benchmark Matching}
\label{sec:ned}
\label{sec:iou}

The evaluation wrapper converts both model outputs into the released KVP10k
schema and calls the benchmark-compatible evaluator
implementation~\cite{kvp10k,kvp10k_repository}. Predicted and target KVP types
must agree. Greedy matching follows prediction order and assigns each target
item at most once.

For predicted text $\hat{t}$ and target text $t$, Normalised Edit Distance
is~\cite{levenshtein}
\[
  \operatorname{NED}(\hat{t},t)
  =\frac{\operatorname{Levenshtein}(\hat{t},t)}
         {\max(1,|\hat{t}|,|t|)} ,
\]
and text matches require $\operatorname{NED}<0.2$. For a predicted box $B_p$
and target box $B_t$, Intersection over Union is~\cite{iou}
\[
  \operatorname{IoU}(B_p,B_t)
  =\frac{\operatorname{Area}(B_p\cap B_t)}
         {\operatorname{Area}(B_p\cup B_t)} .
\]
The KVP10k paper describes a strict threshold, but its released code accepts
$\operatorname{IoU}\geq0.3$; this thesis follows the released implementation.
The implementation assigns IoU zero when the union area is zero. A missing or
malformed box fails the location match instead of causing the evaluator to
stop.

\subsection{Aggregation}
\label{sec:f1}

Text-only, location-only, and text+location metrics are calculated separately
for Regular, Unkeyed, Unvalued, and All categories. Pages with empty
ground-truth content after category filtering are excluded from that category's
macro average. For the remaining $D$ pages, the evaluator reports
\[
  \bar P=\frac{1}{D}\sum_{i=1}^{D}P_i,\qquad
  \bar R=\frac{1}{D}\sum_{i=1}^{D}R_i,\qquad
  F_1=\frac{2\bar P\bar R}{\bar P+\bar R},
\]
where $P_i$ and $R_i$ are page-level pair precision and recall. The reported
F1 is therefore the harmonic mean of macro precision and macro recall, not a
pooled pair-count F1. It is set to zero when $\bar P+\bar R=0$.

\section{Code Organisation and Reproducibility}
\label{sec:code-organisation}
\label{sec:reproducibility}

The final Mistral path separates page preparation, fixed-epoch training,
inference with raw-response retention, parsing, and benchmark evaluation. The
final discriminative path separates the bbox-scale-fixed loader, entity
pretraining, joint V4 training, bbox-scale audits, prediction export, and
official evaluation. Version-controlled launch scripts fix the environment and
run settings for both paths.

Reproducibility records include fixed split manifests, seeds, per-epoch
checkpoints, complete resume state, configuration fingerprints, source and
weight hashes, raw predictions, and evaluator outputs. These detailed records
remain with the implementation artifacts. The main manuscript records the
scientifically relevant data flow, model configuration, selection rule, and
evaluation semantics.
